# {{ title }}

AI coding agents are only as good as what they can see. Tell one "it's broken" and it reads code, guesses, and confidently fixes the wrong thing. Give it a trace ID and well-structured telemetry, and it can follow a failing request across services to the exact line that caused it.

This session covers the telemetry that makes that possible in .NET. We'll start with structured logging using message templates, then traces and spans with `System.Diagnostics` Activities. Next is OpenTelemetry, and why exporting over OTLP beats tying your code to a vendor SDK. Last is how `traceparent` and baggage carry context across service boundaries. Along the way we'll look at the small mistakes that silently break correlation, several of which I hit while building the demo.
